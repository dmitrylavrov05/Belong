# CARCAR на власному сервері Ubuntu 24.04

Замість Netlify: nginx віддає статичні файли з `autoservice/app`, HTTPS від Let's Encrypt (безкоштовно),
оновлення з GitHub кожні 5 хвилин. Кредитів і лімітів на деплой немає — платите лише за сервер.

## Що потрібно

1. **Сервер з Ubuntu 24.04** і публічною IP-адресою (VPS від ~3–5 $/міс: Hetzner, DigitalOcean, Contabo, українські хостинги).
   Домашній компʼютер теж підійде, якщо роутер пробрасує порти 80 і 443 і в провайдера «білий» IP.
2. **Домен**, що вказує на IP сервера (запис A). Без домену немає HTTPS, а без HTTPS не працюють мікрофон для дзвінків,
   сповіщення й офлайн-режим. **Немає домену — не страшно:** скрипт сам візьме безкоштовне імʼя
   `<IP>.sslip.io` (наприклад, `185.166.155.225.sslip.io`), воно вказує на IP сервера, і на нього видається сертифікат.
3. Якщо репозиторій приватний — токен GitHub з правом читання (Settings → Developer settings → Fine-grained tokens).

## Встановлення

```bash
git clone --depth 1 --branch claude/car-wash-tire-service-app-npsdxv https://github.com/dmitrylavrov05/Belong.git
cd Belong/deploy/ubuntu
sudo bash setup.sh                                  # без домену → https://<IP>.sslip.io
sudo bash setup.sh --domain carcar.example.com      # зі своїм доменом (--email — за бажанням)
```

Приватний репозиторій: у обох командах замість `https://github.com/...` — `https://<токен>@github.com/...`,
а в `setup.sh` додайте `--repo https://<токен>@github.com/dmitrylavrov05/Belong.git`.

Після завершення:
- клієнт — `https://ваш-домен/`
- CarCar Business — `https://ваш-домен/pro.html`
- адмінка — `https://ваш-домен/admin.html`

## Спільні дані — всі бачать одне й те саме

Разом із сайтом ставиться сервер CARCAR (`deploy/server/carcar_sync.py`, служба `carcar-sync`).
Клієнти, мийки й адмінка на різних телефонах бачать ті самі записи, ціни, відгуки, чати й дзвінки — зміни
доходять за 1–2 секунди без перезавантаження.

**Права доступу перевіряє сервер**, а не браузер: клієнт бачить лише свої записи, баланс і повідомлення
(чужі записи — тільки як «час зайнятий»), мийка — записи своїх мийок, причому номер клієнта їй не показується;
адмінка — усе. Змінити чужий запис, «оплатити» запис без банку, схвалити власну мийку чи підтвердити собі IBAN не можна.

- Дані: `/var/lib/carcar/data.db` (SQLite), щодня о 04:00 копія в `/var/backups/carcar` (зберігаються 14 днів).
  Відновлення — див. `backup.py`. Почати з чистого аркуша:
  `sudo systemctl stop carcar-sync && sudo rm /var/lib/carcar/data.db && sudo systemctl start carcar-sync`.
- Стан: `systemctl status carcar-sync`, журнал — `journalctl -u carcar-sync -n 50`.

## Налаштування: `/etc/carcar/config.json`

Файл створює `setup.sh`; ключі туди вписуєте ви **прямо на сервері** (не надсилайте їх у чати й листи).
Після кожної зміни: `sudo systemctl restart carcar-sync`.

```json
{
  "admin_password_hash": "…створює setup.sh…",
  "turn": { "secret": "…створює setup.sh…", "host": "185.166.155.225.sslip.io" },
  "telegram_token": "123456:ABC…",
  "telegram_bot": "carcar_login_bot",
  "liqpay": { "public_key": "sandbox_i…", "private_key": "sandbox_…", "sandbox": true },
  "demo_login": false,
  "demo_wash": false,
  "demo_places": false
}
```

### Пароль адмінки

`setup.sh` створює його сам і показує в кінці (копія — `/root/carcar-admin-password.txt`). Змінити:

```bash
sudo python3 /opt/carcar/deploy/server/carcar_sync.py --config /etc/carcar/config.json --set-admin-password 'новий-пароль'
sudo systemctl restart carcar-sync
```

### Вхід клієнтів через Telegram (безкоштовно, замість SMS)

1. У Telegram відкрийте **@BotFather** → `/newbot` → імʼя (`CARCAR вхід`) і логін бота (наприклад, `carcar_login_bot`).
2. BotFather надішле токен. Впишіть його в `telegram_token`, а логін бота без `@` — у `telegram_bot`.
3. `sudo systemctl restart carcar-sync`. На екрані входу зʼявиться «Увійти через Telegram»: бот попросить
   поділитися номером, сервер перевірить, що номер належить саме цьому акаунту Telegram, і клієнт увійде.
   Той самий бот надсилає сповіщення про записи (кнопка в налаштуваннях обох застосунків).

Поки бота немає, працює **демо-вхід** за номером без перевірки (`demo_login`, типово ввімкнений, коли немає токена).
Коли бот запрацює, поставте `"demo_login": false`. `"demo_wash": false` вимикає демо-кабінет мийки
(кнопку «Демо» в CarCar Business) — увімкніть це, щойно підключите справжні мийки.
`"demo_places": false` ховає від клієнтів вигадані мийки («Блиск», «Хвиля» та інші) — у каталозі лишаються тільки
справжні, що пройшли реєстрацію й перевірку в адмінці. В адмінці вони позначені «Демо, приховано від клієнтів».

### Оплата карткою (LiqPay)

1. Зареєструйтеся на [liqpay.ua](https://www.liqpay.ua) (потрібен ФОП/ТОВ і рахунок у ПриватБанку або іншому банку).
2. У кабінеті магазину — «Налаштування» → «API»: публічний і приватний ключі. Впишіть їх у `liqpay`.
3. Спершу `"sandbox": true` — тестові платежі без списання. Перевірили — `false`.

Що відбувається: клієнт натискає «Оплатити» → сторінка LiqPay → після оплати банк повертає його на картку запису,
а серверу надсилає підписане підтвердження (`/api/pay/liqpay/callback`). Тільки тоді запис стає «оплаченим»
і мийка бачить його. Не оплатили за 15 хвилин — час звільняється. Скасування з поверненням
(мийка не підтвердила, скасування вчасно) — сервер сам просить LiqPay повернути гроші на картку.
Без ключів застосунок працює з демо-оплатою, як раніше.

### Сповіщення

- **Push** (на телефон, навіть коли застосунок закрито): ключі VAPID створюються самі (`/var/lib/carcar/vapid.pem`).
  На iPhone push працює, лише якщо застосунок додано на головний екран (iOS 16.4+).
- **Telegram** — якщо налаштовано бота (див. вище).
- Для мийок діє налаштування «Вимикати поза робочим часом» — сервер не надсилає push і Telegram у неробочі години.

### Дзвінки (TURN)

`setup.sh` ставить **coturn**: голос іде через ваш сервер, коли прямого зʼєднання немає (мобільний інтернет,
суворі роутери). Паролі тимчасові (12 годин), їх видає сервер CARCAR. Відкриті порти: 3478 (UDP/TCP), 49160–49200 (UDP).
Якщо в хостера є окремий брандмауер у панелі — відкрийте ці порти й там.

### Юридичні сторінки

`autoservice/app/legal/`: політика конфіденційності, умови для клієнтів, договір для мийок. Це шаблони —
впишіть реквізити замість `[позначок]` і покажіть юристу.

### Демо-режим — в адмінці

Адмінка → «Демо-режим»: вигадані мийки в каталозі, демо-кабінет мийки й вхід клієнтів без перевірки номера.
Перемикачі діють одразу на всіх телефонах (рішення адмінки важливіше за `demo_*` у конфігурації).
Вхід без перевірки не вимикається, поки не підключено бота Telegram, — інакше клієнти не змогли б увійти.

## Багато користувачів одночасно

Сервер тримає дані в памʼяті й віддає кожному лише потрібне: чужі записи — тільки на сьогодні й далі
(та 30 днів для статистики відповідей мийок), спільну частину відповіді збирає один раз для всіх.
Телефон, який чекає змін, будять лише зміни, які він бачить. nginx стискає відповіді й обмежує флуд
(30 запитів/с з адреси), ліміти зʼєднань підняті (`worker_connections 8192`, `LimitNOFILE=65535`).

Перевірка на 4 ядрах (`deploy/server/loadtest.py`, у базі 3000 записів):

| Одночасно відкрито | Нових записів | Збереження запису (медіана / 95%) | Зміна доходить до всіх (медіана / 95%) | Помилки |
|---|---|---|---|---|
| 300 телефонів | 8 за секунду | 0,3 / 0,5 с | 0,13 / 0,3 с | 0 |
| 1000 телефонів | 2 за секунду | 0,6 / 0,9 с | 0,4 / 0,7 с | 0 |

Для порівняння, до оптимізації вже на 300 телефонах запис зберігався ~4 с.
Що варто памʼятати: сервер — один процес Python, тож для десятків тисяч одночасних користувачів
знадобиться інша архітектура (окремі записи в базі замість одного спільного списку, черга повідомлень).
Сервер на 2 ГБ памʼяті й 2 ядра вистачить на сотні одночасних користувачів; трафік — з тарифом без жорстких лімітів.

**Щоб нові налаштування nginx і служби запрацювали, запустіть `setup.sh` ще раз** (автооновлення оновлює код,
а не системні налаштування).

## Що ще не зроблено

- SMS-вхід і власний домен (зараз — Telegram і `*.sslip.io`).
- Ціни й суми рахує застосунок; сервер перевіряє права й оплату, але не перераховує вартість послуг.
- Баланс CARCAR і бонуси клієнт може змінювати лише у своєму гаманці; справжні гроші — тільки через LiqPay.

## Оновлення

Сервер сам підтягує гілку кожні 5 хвилин. Оновити одразу: `sudo systemctl start carcar-update`.
Перевірити: `systemctl list-timers carcar-update.timer`, журнал — `journalctl -u carcar-update -n 20`.

## Що робить скрипт

- ставить nginx, git, certbot, coturn, python3-cryptography і вмикає брандмауер (SSH, 80, 443, TURN);
- клонує гілку в `/opt/carcar` і налаштовує nginx (`nginx.conf` поруч): сторінки й скрипти без кешу,
  щоб оновлення приходили одразу, шрифти й звук — з кешем, `.git` закрито;
- отримує сертифікат Let's Encrypt і вмикає перенаправлення на HTTPS (сертифікат продовжується сам);
- створює `/etc/carcar/config.json`, пароль адмінки й секрет TURN (повторний запуск їх не змінює);
- запускає служби `carcar-sync` (сервер), `coturn`, таймери `carcar-update` (автооновлення; сервер перезапускається,
  лише коли змінився код у `deploy/server`) і `carcar-backup` (щоденна копія бази).

Оновлюєте вже встановлений сервер — просто запустіть `setup.sh` ще раз (так само, як першого разу).
